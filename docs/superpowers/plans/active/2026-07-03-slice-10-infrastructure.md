> **Plan Status:** Active
>

>
> **For agentic workers:** Execute one task at a time. Do not start a later task until the preceding task's checks pass. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provision a deployable private Azure implementation of password-hook-service that on-premises portal web servers call over an approved site-to-site VPN through an existing Azure Application Gateway WAF_v2 private frontend, and replace the per-replica in-memory sync-status store with an Azure Managed Redis-backed store, so `login_bootstrap` deduplication and out-of-order protections remain correct across replicas and restarts.

**Architecture:** This repository's Terraform creates or consumes the approved hybrid-network resources (VNet, route-based site-to-site VPN, private DNS resolution, and ACA infrastructure subnet), then deploys an internal Azure Container Apps environment, Service Bus, Key Vault, Application Insights/Log Analytics, Azure Managed Redis, the approved existing ACR, and a single user-assigned runtime identity. The existing Application Gateway owner's state and pipeline—not a partial `azurerm_application_gateway` resource in this repository—add the dedicated static private frontend, HTTPS listener, WAF policy association, backend setting, probe, and routing rule without changing existing public paths. This repository exports and documents the exact backend and listener contract for that handoff. On-premises portal web servers resolve a private HTTPS hostname to the Application Gateway private frontend and reach it over the VPN; the gateway re-encrypts traffic to internal ACA. The application accepts a forwarded client address only when the immediate peer is in an explicitly configured trusted-proxy CIDR, so the application allowlist and per-client rate limit remain meaningful behind Application Gateway and ACA. The application uses the runtime identity for Key Vault, Service Bus, Azure Monitor custom metrics, Azure Managed Redis, and ACR image pulls; it stores no runtime connection strings. The Redis store preserves the existing `syncstatus.Store` semantics, including a deterministic equal-`SourceEnqueuedAt` state ordering. Runtime secrets remain operator-injected into Key Vault and never enter Terraform inputs, state, or outputs.

**Tech Stack:** Go 1.26, `github.com/redis/go-redis/v9`, `github.com/redis/go-redis-entraid`, Azure Managed Redis with Microsoft Entra authentication and TLS, Terraform `>= 1.8.0`, AzureRM 4.x, AzAPI, Azure Container Apps, Azure Service Bus Premium, Azure Key Vault RBAC, Azure Monitor/Application Insights.

## Active Constraints

- Production must use `SERVICEBUS_AUTH_MODE=managed_identity`; do not create Service Bus SAS rules or inject a Service Bus connection string for production.
- Azure Managed Redis must use Entra authentication and TLS. Disable access-key authentication after the runtime identity's data access is provisioned; do not put Redis access keys in Key Vault, app config, Terraform state, or docs.
- Preserve the existing sync-status state-machine semantics: unknown UPNs are unsynced; `sync_pending` suppresses only fresh `login_bootstrap` events; `synced` suppresses `login_bootstrap`; `sync_failed` allows a later bootstrap; stale outcome writes are ignored by `SourceEnqueuedAt`. For equal source timestamps, use the monotonic precedence `sync_pending < sync_failed < synced`; equal status writes are idempotent and do not refresh timestamps or TTLs. Apply the same rule to memory and Redis stores.
- The shared-store outage posture remains fail-open for hook deduplication and best-effort for worker status recording, matching existing `migration.Service` and `worker.Worker` behavior. It must never cause password plaintext, ciphertext, queue bodies, tokens, or secret values to be logged.
- Use Azure Key Vault RBAC (`enable_rbac_authorization = true`), not legacy access policies. Runtime needs `Key Vault Secrets User`; named operators need `Key Vault Secrets Officer` only where secret injection/rotation is intended.
- Include the completed Slice 8A telemetry requirements: Application Insights, an ACA managed OpenTelemetry agent configured through AzAPI, and `Monitoring Metrics Publisher` on the chosen custom-metrics resource. Do not set `OTEL_EXPORTER_OTLP_ENDPOINT` in the app spec because ACA injects it. Before deployment, change the current HTTP OTLP trace exporter to the managed agent's supported gRPC transport and test that the platform-injected endpoint satisfies application validation.
- The hook API must be internal-only: on-premises portal web servers reach a private Application Gateway WAF_v2 frontend over an approved route-based site-to-site VPN using a private DNS name and HTTPS; the gateway reaches the ACA backend over the environment's private static IP (never a public ACA ingress endpoint). Do not expose the hook through public ACA ingress, Front Door, or an internet-facing reverse proxy in this slice. Note: "internal-only" here describes the network path, not the Container App's `ingress.external_enabled` flag — that flag ended up needing to be `true` for the Application Gateway backend to work at all; see the "Container App ingress mode" row in `2026-07-03-slice-10-private-network-decisions.md`.
- The plan must either create the required VPN/DNS resources or consume approved existing hub-network resources; it must never silently assume either model. Public/private endpoint decisions for ACR, Key Vault, Service Bus, and Managed Redis must be explicit and validated against the selected network topology.
- Reuse the approved existing staging/production Application Gateway WAF_v2 resources. Its current owner must add the isolated password-hook path through the existing state/pipeline. This repository must not import, recreate, or partially manage the gateway. Use a staging-first change window and rollback procedure for every gateway update.
- Do not implement Front Door, alert rules, dashboards, CI/CD, scanner gates, or production runbooks in this slice. Implement and test a trusted-proxy source-address policy before infrastructure deployment; never trust a forwarded header from an untrusted immediate peer.
- Globally constrained resource names must use validated normalized prefixes plus a state-stable lowercase alphanumeric random suffix. Validate limits before `terraform apply`; do not describe a random suffix as deterministic.
